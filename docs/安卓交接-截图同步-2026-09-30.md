# 交接说明：截图与笔记同步

日期：2026-09-30  
来源：Windows 桌面版已实现的行为。截图接口已部署到 `https://subtitle.gcsfg.work`。  
目的：安卓版和电脑使用同一套截图目录、同一套笔记格式、同一套云端合并规则。手机和电脑填同一个用户名，就是同一个用户。

账号、字幕、标签仍按 `docs/安卓交接-云同步-2026-09-29.md`。配套文件夹、时间线、播放日志仍按 `docs/安卓交接-配套文件夹与播放日志-2026-09-30.md`。创建/编辑截图的界面见 `docs/安卓交接-创建编辑截图-2026-10-01.md`。查看截图与截图管理见 `docs/安卓交接-截图查看与截图管理-2026-10-01.md`。本文只覆盖截图数据怎么存、怎么同步。

`GET /api/sync` 不返回截图。截图用下面单独的四个接口。截图不能分享给其他用户，没有对应的分享接口。

## 1. 一部视频的截图是什么

身份仍是视频内容的 SHA-256，64 位小写十六进制，不是文件名。改名、换目录、原样复制，哈希不变，截图仍对得上。重新压制、剪辑、转码之后是新视频，旧截图不会自动跟过去。

云端唯一范围是 `(用户, 视频哈希, 截图编号)`。截图编号是 12 位小写十六进制，由创建它的那台设备生成。同一张图在手机和电脑上靠这个编号认成同一张。

本地文件放在配套文件夹里：

```text
电脑.mp4.data/
  screenshot/
    screenshots.json
    a1b2c3d4e5f6.png
```

没有截图时，不要留下空的 `screenshot` 目录。云端下载来的压缩图没有原图时，文件名是 `a1b2c3d4e5f6.webp`，和说明写在同一个目录。本机自己截的图保持 PNG，不要在本地再存一份压缩图。

`screenshots.json`：

```json
{
  "version": 1,
  "screenshots": [
    {
      "id": "a1b2c3d4e5f6",
      "title": "画面标题",
      "time": 12.5,
      "frame": 375,
      "image": "a1b2c3d4e5f6.png",
      "created_at": 1758000000000,
      "updated_at": 1758000065000,
      "notes": [
        {
          "id": "b1b2c3d4e5f6",
          "text": "笔记正文",
          "created_at": 1758000000000,
          "updated_at": 1758000065000,
          "box": {
            "x": 0.18,
            "y": 0.56,
            "width": 0.64,
            "height": 0.3,
            "background": "#FFFFFF",
            "opacity": 0.85,
            "font": 0.06,
            "color": "#1A1A1A",
            "align": "center"
          }
        }
      ]
    }
  ]
}
```

- `time` 是视频里的秒，用来定位和抽帧。
- `frame` 表示这张图来自这部视频的哪一帧。没有帧号时写 `null`。抽帧仍用 `time`，不要用帧号去跳。
- `created_at`、`updated_at` 是 Unix 毫秒。改标题、笔记或框的位置时更新 `updated_at`。
- 笔记编号也是 12 位小写十六进制。没有框时不要写 `box`，预览里用默认位置。
- `x`、`y`、`width`、`height`、`font` 都是相对底图的比例，不是像素。`font` 是底图高度的比例，范围 0.02 到 0.16。旧数据里大于 1 的数字是像素，按 480 像素高换算。
- `opacity` 范围 0.15 到 1。
- `align` 只接受 `left`、`center`、`right`。
- 文字颜色：黑 `#1A1A1A`（默认）、白 `#FFFFFF`、黄 `#FFD54A`、红 `#E53935`、蓝 `#1565C0`、绿 `#2E7D32`、紫 `#7A4EB5`。底色默认白 `#FFFFFF`。

列表里截图和字幕按时间排在一起。同一毫秒时，字幕行在前，截图在后。点截图跳到 `time`。

## 2. 什么时候同步

已登录并且当前已联网时，在后台做，不要进度框，不要询问。未联网就跳过，不要弹错误框。

1. 打开视频。
2. 在本机新建、修改或删除一张截图之后。

先写本地文件。云端失败不影响本机已经保存的图和笔记。

本机要记住「这台设备上次同步后，这部视频有哪些截图编号」。这份记录按用户和视频哈希放在应用自己的目录里，不要放进 `视频全名.data`。删掉配套文件夹不能把这份记录清掉，否则无法区分「用户在播放器里删了图」和「用户把整个目录删了想重新下载」。

## 3. 说明怎么合并

桌面版用一次 `PUT` 完成上传和取回。也可以先 `GET /api/screenshots?video_hash=` 只读取。

```http
PUT /api/screenshots
Authorization: Bearer <access_token>
Content-Type: application/json
```

```json
{
  "video_hash": "<64位小写十六进制>",
  "video_stem": "电脑",
  "shots": [
    {
      "id": "a1b2c3d4e5f6",
      "title": "画面标题",
      "time": 12.5,
      "frame": 375,
      "created_at": 1758000000000,
      "updated_at": 1758000065000,
      "notes": []
    }
  ],
  "baseline_ids": ["a1b2c3d4e5f6"]
}
```

返回：

```json
{
  "video_hash": "<64位>",
  "shots": [
    {
      "id": "a1b2c3d4e5f6",
      "title": "画面标题",
      "time": 12.5,
      "frame": 375,
      "created_at": 1758000000000,
      "updated_at": 1758000065000,
      "notes": [],
      "has_image": true,
      "image_hash": "<64位小写十六进制，没有图时是空字符串>"
    }
  ]
}
```

合并规则：

- 云端没有这个编号：按本次上传新建。
- 两边都有：`updated_at` 更大的一方保留标题、时间、帧号和笔记。较旧的上传不会把较新的笔记盖掉。
- 已有图片时，这次合并不替换图片。
- `baseline_ids` 里有、本次 `shots` 里没有的编号，服务器删除，并删掉对应的压缩图。
- `baseline_ids` 为空时，服务器不删除任何图。本机没见过的编号会在返回里带下来，要写入本地，不要当成多余数据丢掉。

`baseline_ids` 只在下面两种情况填写上次见过的编号：

1. 这个视频文件的 `screenshot/screenshots.json` 还在。清单里少了的编号，就是用户删掉的图。
2. 用户在播放器里把这个文件的截图全部删光。删光这一动作要先记在应用自己的基线里，再同步。

配套文件夹不在、或这个文件名下还没有 `screenshots.json` 时，`baseline_ids` 必须传空数组。这包括用户删掉整个 `.data` 后重新打开，也包括视频改名、换目录后第一次打开。此时只下载云端已有的截图。把旧编号传上去，服务器会把云端的图删掉。

一次最多 500 张。一张最多 100 条笔记。笔记 JSON 不超过 20 万字节。标题不超过 4000 字。不合规则返回 400，`detail` 直接显示给用户，例如「截图编号无效」「截图说明无效」「截图笔记过长」。

同步结束后，把返回结果里的编号记成这台设备的新基线，并记下这次打开的视频路径。播放器里主动删光时做的标记，同步成功后清掉。

返回的说明比本地新，就用返回的标题、时间、帧号和笔记更新本地。同步过程中用户又新截的图留在本地，下一次再传。

## 4. 图片怎么补、怎么传

对返回结果里的每一张：

1. 本地已有 `{编号}.png`：用这张原图，不下载。
2. 没有原图，且 `frame` 不是 `null`：按 `time` 从当前视频抽出一帧，存成 PNG。
3. 抽不出，或没有帧号，且 `has_image` 为 true：下载压缩图，存成 `{编号}.webp`。
4. 本地文件是 PNG，且 `has_image` 为 false：把原图压成 WebP 再上传。云端已经有图就不要再传。

压缩规则：长边不超过 1280，不放大小图，WebP 质量 40。请求体是 WebP 字节，不是 JSON。上限 2MB。

```http
PUT /api/screenshots/{video_hash}/{shot_id}/image
Authorization: Bearer <access_token>
Content-Type: image/webp
```

成功返回这一张的说明，`has_image` 为 true。还没有先同步说明时返回 404，`detail` 是「请先同步截图说明」。不是 WebP 或超过 2MB 时返回 400，「截图需要是 2MB 以内的 WebP」。

```http
GET /api/screenshots/{video_hash}/{shot_id}/image
Authorization: Bearer <access_token>
```

成功正文是 `image/webp`。没有这张图时 404，「没有这张截图」。其他用户的令牌也是 404，不要提示成「无权限」后再去试别的账号。

## 5. 普通截图

预览里有一个「普通截图」按钮，放在「显示笔记」前面，不要挨着「下一图」。

它只在本机把当前底图和当前显示出来的笔记合成一张 JPEG，弹出保存对话框。记住上次保存的文件夹，下次从那里开始。默认文件名是 `视频名-截图标题.jpg`。标题为空时用「截图」。这个文件不上传，也不写进 `screenshots.json`。

隐藏的笔记不要画进去。选中笔记时的高亮边和缩放手柄不要画进去。

---

## 6. 安卓这次要做出的结果

1. 截图说明和图片放在 `视频全名.data/screenshot/`。
2. 打开视频，以及新建、修改、删除截图之后，按第 3、4 节后台同步。
3. 删掉整个配套文件夹后再打开，重新下载，不要把云端截图删掉。
4. 只在播放器里删掉的截图，才从云端删除。
5. 原图留在本机。上传只传压缩后的 WebP，而且不覆盖云端已有的图。
6. 笔记的位置、颜色、透明度用第 1 节的比例字段，电脑上写的框在手机上仍落在画面的同一相对位置。
7. 截图只属于当前账号。

---

## 7. 不要做

- 不要从 `GET /api/sync` 里读截图。那里没有。
- 不要做截图分享，也不要在用户之间展示。
- 不要因为本地没有 `screenshots.json` 就在 `baseline_ids` 里带上旧编号。
- 不要把基线文件放进 `视频全名.data`。
- 不要用帧号抽帧。抽帧用 `time`。
- 不要把云端 WebP 覆盖本机已经存在的 PNG，也不要在原图还在时再存一份本地压缩图。
- 不要重复上传云端已经有的图片。
- 不要把「普通截图」导出的 JPEG 当成云端截图上传。
- 不要改服务器。截图表和四个接口已经可用。
