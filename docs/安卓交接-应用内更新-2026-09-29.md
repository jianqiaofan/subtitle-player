# 交接说明：安卓应用内更新

日期：2026-09-29  
目的：改完代码并打出 APK 后，不用微信或数据线传文件。手机或平板在应用里点「安装更新」，从已经配好的服务器下载并交给系统安装。

安卓工程里已有签名和工程文件。本文件只规定更新协议和客户端行为。不要改字幕服务器、Nginx、数据库，也不要动采购系统和 FansTool。

---

## 1. 服务器上已经有的地址

更新文件单独放在：

- 版本说明：`https://subtitle.gcsfg.work/releases/latest.json`
- 安装包：`https://subtitle.gcsfg.work/releases/app.apk`

`latest.json` 现在是占位，`versionCode` 为 0，还没有真正的 APK。第一次正式发布后，这两个地址会被覆盖成新版本。

版本说明格式：

```json
{
  "versionCode": 2,
  "versionName": "1.0.2",
  "url": "https://subtitle.gcsfg.work/releases/app.apk",
  "sha256": "64位小写十六进制",
  "notes": "这次更新做了什么"
}
```

只下载 `url` 指向 `https://subtitle.gcsfg.work/releases/` 的文件。下载完成后用 SHA-256 和 `sha256` 比对，不一致就删除文件并提示更新包损坏，不要调起安装。

---

## 2. 版本号和签名

- 应用里的 `versionCode` 是整数。服务器上的 `versionCode` 更大时才提示更新。
- 每次发布都把 `versionCode` 加 1。`versionName` 给人看，不参与比较。
- 永远用同一把签名密钥覆盖安装。换密钥后系统会拒绝更新，只能卸载重装，本地学习数据会丢。
- 密钥文件和密码不要放进 git，不要写进交接或聊天。工程里如果还没有密钥，就在工程旁边生成一把，并让以后所有调试包、正式包都用它。
- 已经装在手机上的旧包如果是另一把密钥打的，第一次改用这把密钥时需要卸载重装。从这一版起，后续都走「安装更新」。

---

## 3. 应用里要做的「安装更新」

放在设置页，按钮文字用「安装更新」。

流程：

1. 读取 `https://subtitle.gcsfg.work/releases/latest.json`。
2. `versionCode` 不大于本机版本时，提示「已是最新版本」。
3. 更高时展示 `versionName` 和 `notes`，用户确认后再下载 `url`。
4. 校验 SHA-256。
5. 交给系统安装器。安卓 8 及以上先确认本应用有「安装未知应用」权限，没有就带用户去系统设置打开。
6. 用 `FileProvider` 把 APK 变成 `content://` 再交给系统。不要用 `file://`。
7. 安装界面由系统弹出，用户再点一次安装。应用不能静默安装。

网络失败时显示失败原因。不要在每次冷启动时强制下载；用户点按钮再检查即可。

带这个按钮的第一版，仍然要用一次无线调试或数据线装到设备上。装上之后，后面的版本都用这个按钮。

## 4. 电脑上的发布命令

Windows 桌面仓库里已经有发布脚本：

`subtitle_server/deploy/publish-android.ps1`

在桌面仓库根目录执行，把刚打好的已签名 APK 传上去：

```powershell
powershell -File subtitle_server\deploy\publish-android.ps1 -Apk "APK的完整路径" -VersionCode 2 -VersionName "1.0.2" -Notes "这次更新做了什么"
```

脚本会计算 SHA-256，写 `latest.json`，并上传到上面的两个地址。`VersionCode` 必须大于上一版，并且和 APK 里的 `versionCode` 一致。

安卓工程负责打出这个已签名 APK。上传用上面的脚本，不要在安卓工程里再改服务器。

---

## 5. 坐在电脑前时的无线调试

同一 Wi-Fi 下，用无线调试代替数据线：

1. 平板或手机打开开发者选项里的「无线调试」。
2. 点「使用配对码配对设备」，记下 IP、端口和六位配对码。
3. 电脑执行 `adb pair IP:端口`，输入配对码。
4. 再执行 `adb connect IP:连接端口`。连接端口和配对端口不是同一个，以无线调试主页面上的地址为准。
5. Android Studio 里选中这台设备，直接 Run。

配对码只在当时有效。无线调试页面上的 IP 变了，就重新配对。
