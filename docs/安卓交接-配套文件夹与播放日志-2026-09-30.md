# 交接说明：配套文件夹、无字幕时间线、播放日志

日期：2026-09-30  
来源：Windows 桌面版今天已实现的行为。播放日志接口已部署到 `https://subtitle.gcsfg.work`。  
目的：安卓版和电脑使用同一套本地目录、同一套打开视频规则、同一套播放记录。手机和电脑填同一个用户名，就是同一个用户。

账号、字幕上传、标签合并、别人分享的字幕，仍按 `docs/安卓交接-云同步-2026-09-29.md`。本文只覆盖今天新增和改过的本地摆放、打开时的字幕来源、退出时的同步询问，以及播放日志。两份一起看。截图与笔记见 `docs/安卓交接-截图同步-2026-09-30.md`。应用内更新仍见 `docs/安卓交接-应用内更新-2026-09-29.md`。

安卓只做客户端。不要改服务器、Nginx、数据库，也不要动服务器上的采购系统和 FansTool。

## 1. 配套文件夹

视频文件留在原来的位置。每个视频旁边有一个文件夹，和视频同一层，名字是「视频全名」再加 `.data`。

```text
课程/
  电脑.mp4
  电脑.mp4.data/
    电脑.srt
    电脑_中文.srt
    电脑.srt.tags.json
    电脑_中文.srt.tags.json
    电脑.mp4.videohash.json
    playback.json
```

文件夹名必须带上扩展名。`电脑.mp4` 和 `电脑.mkv` 各有各的 `.data`。不能把文件夹做成和视频文件完全同名。

文件夹里面的字幕名、标签名保持原来的规则：字幕是「视频主文件名 + 语言后缀」，标签是「字幕文件名 + `.tags.json`」。云端下载下来的文件也按当前视频的主文件名加语言后缀，写进这个 `.data`，不要写到视频旁边。

哈希文件名仍是 `视频全名.videohash.json`，位置改到 `.data` 里面。旧版写在视频旁边的，打开视频时移进去。`size` 和 `mtime_ns` 与视频一致时直接用里面的 `hash`。

主文件名更长的视频仍优先认领字幕。`第1课_复习.srt` 属于 `第1课_复习.mp4.data`，不要收进 `第1课.mp4.data`。

AI 笔记和生词表这次没有搬进 `.data`，仍可留在视频旁边。不要把它们误当成字幕或标签收走。

## 2. 打开视频时字幕从哪里来

先整理本机，再决定要不要问云端。整理不能等网络。

1. `.data` 里没有同名字幕，视频旁边有：把字幕和它旁边的 `字幕文件名.tags.json` 搬进 `.data`，再打开。转录工具默认把新字幕放在视频旁边，所以这一步必须有。
2. 两个位置都有同名文件：弹出选择。每一份都要写出完整路径、创建时间、最后更新时间。用户选中的留在 `.data`，另一份字幕及其标签删除。用户这次取消，就先用 `.data` 里已有的那份；下次重新进入播放器再打开这部视频时还要问。
3. 两边都没有字幕，并且当前已联网：后台向云端要自己的字幕。要到了就写入 `.data`。未联网不要发请求，也不要弹「无法连接」。
4. 云端也没有字幕：字幕列表改为时间线，见第 3 节。
5. 视频旁边没有字幕，`.data` 里已经有：联网后后台检查云端有没有更新。有更新再询问是否写入 `.data`。规则与原来的「自己的字幕 / 自己的标签」相同，只是落盘目录改成 `.data`。

别人分享的字幕仍只在本地一份有效字幕都没有时才提供。下到的文件同样写入 `.data`。

所有自动的云端同步，包括打开时检查、播放日志追加，都先判断当前设备已联网。未联网就跳过，不要弹错误框。用户在菜单里主动点的上传、登录，失败时仍要显示服务器返回的 `detail`。

## 3. 没有字幕时的时间线

时间线只在列表里出现，不写成 `.srt` 或 `.vtt`。

步距默认值：

| 视频时长 | 默认步距 |
|---|---|
| 小于等于 1 分钟 | 10 秒 |
| 小于等于 10 分钟 | 30 秒 |
| 大于 10 分钟 | 60 秒 |

列表上方提供选择：5 秒、10 秒、15 秒、30 秒、1 分钟、2 分钟、5 分钟。每一行是一个时间段，点击跳到该段起点，并随播放高亮、滚动。

时间线上的标签要能同步。标签文件放在 `.data` 里：

`电脑.mp4.data/电脑_时间线.srt.tags.json`

云端语言后缀是 `_时间线.srt`。只上传这份标签，不要上传时间线正文，也不要生成 `电脑_时间线.srt`。标签文档里的 `subtitle_file` 填 `电脑_时间线.srt`。每条标签的 `start` 用打标签时那一段的开始时间（秒）。

以后这部视频有了真正的字幕：列表改显示字幕，不再显示时间线。时间线上还在的标签，按 `start` 落入哪条字幕的时间范围，挂到那一行，并写入该字幕自己的 `.tags.json`。同一条用原来的标签 `id`，避免重复挂上。时间线文档里这些标签记成取消，下次标签同步会把取消传到云端。

## 4. 退出时询问要不要上传

观看过程中字幕正文改过，或标签改过，在下面三个时机询问：

- 关闭播放器
- 改打开另一个视频
- 当前视频播放到结尾

一个对话框里两件事：

- 可勾选「同步字幕」。这次没改字幕就不要让它可选。
- 可勾选「同步标签」。这次没改标签就不要让它可选。
- 可勾选「不再询问，在本设备，该视频下回采用相同的同步策略」。

按钮是「同步」和「暂不同步」。勾了「不再询问」之后，这部视频在这台设备上按这次的勾选自动处理：勾了的项目有改动就上传，没勾的不再问。这个选择只存在本机，不上传，也不跟其他用户共享。

未登录或未联网时不要弹这个框。未联网时把「有改动还没同步」记在本机，下次这部视频在已联网时再问，或按已记住的策略上传。

已在云端标记为共享的字幕，这次补传时保持共享。新字幕不要在这个退出框里改成共享。

## 5. 播放日志

用于统计这部视频的学习总时长，并按时间查看每一次播放。不能在用户之间共享。`GET /api/sync` 和 `GET /api/shares` 都不要返回它。

### 5.1 本地文件

`电脑.mp4.data/playback.json`

```json
{
  "version": 1,
  "sessions": [
    {
      "id": "32位小写十六进制",
      "started_at": 1758000000000,
      "ended_at": 1758000065000
    }
  ]
}
```

- `started_at`、`ended_at` 是 Unix 毫秒。
- `id` 由本机生成，32 位小写十六进制。同一段播放在两台设备上靠这个编号认成同一条。
- 开始真正播放时写入 `started_at`。此时可以还没有 `ended_at`。
- 暂停、播放结束、换视频、关闭播放器时写入 `ended_at`。
- 短于 1 秒的片段丢掉，不要留在文件里，也不要上传。
- 先写本地文件。云端失败不影响本地记录。

不要把打开文件时为了显示画面而做的极短试播放记进去。

### 5.2 什么时候同步

已登录并且当前已联网时，在两处后台追加，不要进度框，不要询问：

1. 开始播放。把本地已经结束的各段送上去，并取回这个用户在其他设备上的记录，合并进 `playback.json`。正在进行、还没有 `ended_at` 的那一段不要上传。
2. 结束播放。先把 `ended_at` 写入本地，再按同样方式追加同步。

服务器按 `id` 追加。已经存过的编号保持原样，不会被后一次上传改掉。一次最多 500 条。返回的是这个用户、这部视频哈希下的全部记录，按开始时间从新到旧。其他用户调用同一接口，看不到这些记录。

```http
PUT /api/playback
Authorization: Bearer <access_token>
```

```json
{
  "video_hash": "<64位小写十六进制>",
  "video_stem": "电脑",
  "sessions": [
    {"id": "<16到64位小写十六进制>", "started_at": 1758000000000, "ended_at": 1758000065000}
  ]
}
```

```json
{
  "video_hash": "<64位>",
  "sessions": [
    {"id": "...", "started_at": 1758000000000, "ended_at": 1758000065000}
  ]
}
```

也可以 `GET /api/playback?video_hash=`，返回同样的 `video_hash` 和 `sessions`。桌面版用 `PUT` 一次完成追加和取回。

服务器拒绝这些情况，`detail` 为「播放时间无效」或「播放记录编号无效」：

- 时间不在 2020-01-01 到 2100-01-01 的毫秒范围内。
- `ended_at` 小于或等于 `started_at`。
- 一段超过 24 小时。

### 5.3 怎么展示

入口可以放在工具或菜单里，名称用「学习记录」。未打开视频时提示先打开视频。

顶部写学习总时长：把所有已结束片段的 `ended_at - started_at` 相加。展示成「2小时3分4秒」「2分5秒」或「45秒」。

列表每条一行，新的在前：

`2026-09-30 10:25:01  →  2026-09-30 10:40:12    15分11秒`

时间戳按设备时区转成 `yyyy-MM-dd HH:mm:ss`。安卓用 `ZoneId.systemDefault()`。这个时区读不到或无法用于格式化时，用 `Asia/Shanghai`。

没有记录时显示「还没有播放记录。」

## 6. 安卓这次要做出的结果

1. 字幕、标签、哈希、播放日志都放在 `视频全名.data`。
2. 打开视频时按第 2 节处理旧位置、同名二选一、云端和时间线。
3. 没有字幕时列表是时间线，步距和标签规则按第 3 节。
4. 字幕或标签在观看中改过，离开视频时按第 4 节询问，并记住本机策略。
5. 播放日志按第 5 节写本地文件，联网时在开始和结束播放后台追加。学习记录用设备时区显示，没有时区就用上海时间。
6. 播放日志只属于当前账号。

---

## 7. 不要做

- 不要把 `.data` 做成和视频文件完全同名的文件夹。
- 不要把时间线写成字幕文件，也不要把它当成一种可分享的字幕。
- 不要在未联网时做打开视频的自动同步或播放日志同步。
- 不要把播放日志放进分享接口，也不要在用户之间展示。
- 不要用后一次上传覆盖云端已经保存的同一条播放记录。
- 不要改服务器。播放日志表已经建好。
